# ScreenWings P0：WinLicense 虚拟分派器的 RET 假退出（2026-10-13）

研究对象：`ScreenWings.exe`，SHA-256 `481ecd41bef2a33076729680747eb92e4e2964bed89c58825d80f602de19f214`。第一层 `schiffer_stage1.bin` 为 6,758,400 字节，SHA-256 `2a1185bbcc93a049d413a71104ed41623bae61cf2412de5ea015564ea8b4d420`。

**本次直接研究问题：** 第二层虚拟分派是否已经退出保护层、转入原始 ScreenWings 业务 OEP？结果：**还没有发现 OEP。一个表面上的 `RET` 实际仍然跳进 VM handler。**

## P0 新发现：RET 并不表示恢复原始程序入口

此前已经确认两次分派：

| 选择器 | 重定位后 E9 跳转桩 | E9 目标 |
|---:|---|---|
| 803 | `0x4F464D` | `0x4DB0E0` |
| 570 | `0x496308` | `0x5303F3` |
| 893 | `0x4F4CF5` | `0x593011` |

从 `0x5303F3` 清理虚拟上下文后，经 `0x5304C6 JMP ECX` 进入索引 893 的处理器 `0x593011`。

对这一处理器进行受限 x86 子集模拟（**没有执行目标机器码**），并用真实的恢复区字节交叉校验：

1. 假定上下文 `+0x7E` 在此前处理器中被清零，`VIP = 0x4A1366`；读取 `WORD[VIP+6]=0xCEA2` 和 `WORD[VIP+8]=0x3581`。
2. 选择器 `(0xCEA2 + 0x3581) & 0xFFFF = 0x0423 = 1059`，表项地址 `0x6471D3 + 1059×4 = 0x64825F`。
3. 此表项在重定位后为 `0x4D289F`，实际字节以 `E9` 开头，其落点是 `0x5C2E23`。
4. 在 `0x593340` 将表项写入上下文字段 `+0xA7`；到 `0x593436` 重新读取；`0x593453–0x59346A` 构造并覆盖栈槽。
5. `0x593508` 执行 `RET 0`，受限模型中真正出栈的是 `0x4D289F`，仍为保护层的跳转桩。
6. 指令流指针 `VIP` 通过 `DWORD[0x4A1368]=0x000F618B` 更新为 `0x5974F1`。

这揭示一种过去未确认的跳转方式：**虚拟机分派不仅通过 `JMP reg`，还可以预先写入合成的栈返回地址，再通过 `RET` 进入另一条 `E9` 保护跳转桩。**

### 又追到一次 JMP EDX 分派

在 `0x5C2E23` 处理器中：

- 受限模型得到下一索引 **518**；
- 表项位置 `0x6479EB`、跳转桩 `0x4C1B9A`；
- E9 目标 **`0x53CE97`**；
- 原生间接转移指令：**`0x5C32F3 JMP EDX`**；
- `DWORD[0x5974F1]=0xFFF09E7F`（带符号增量），因此 `VIP` 更新为 `0x4A1370`。

这里仍然是保护层内部的间接分派，不是 GUI/OEP。

## P0 严格停机点与模型证据质量

在一个只支持明确 x86 指令子集的非执行模型中，从 `0x593011` 开始处理了 **852 个指令/跳转桩步骤**，已覆盖分派至 `0x53CE97` 的前缀。建立了 3 条条件分支记录，结果均为走 `JBE` 的真分支。内存写入统计：

| 写入区域 | 次数 |
|---|---:|
| 受限 VM 上下文（`0x4C19BC` 附近） | 32 |
| 合成模拟栈 | 5 |
| 其他地址（包括可执行代码区） | **0** |

这只能说明**该模型已覆盖的前缀未发现代码区写入**；绝不意味着 WinLicense 没有后续解密代码。

模型在 **`0x53D2EF`** 停止：连续第二条 `MOV EDI,[EDI]` 将读取低地址 `0x18`，当前模拟状态不满足映像有效地址条件。可能原因包括缺失的前置虚拟上下文、标志计算差异、模拟种子不完整。**从这个位置开始不能继续把模型预测当作已经证实的真实控制流**。

**模拟栈位置敏感性复核：** 将合成 ESP 分别设为 `0x7FFF0000`、`0x6FFF0000` 和 `0x5FFF0000`，3 次都得到相同的 `RET 0x4D289F` → `0x5C2E23`、`JMP 0x4C1B9A` → `0x53CE97`，并在同一 `0x53D2EF` 读取错误处停止。这仅排除当前模型对于这三种栈基址选择的敏感性，不是三次真实 Windows 运行。

初始上下文寄存器及模拟栈是从前面处理器静态推导的条件假设，并非实机寄存器采样。未捕获任何原始 ScreenWings 的运行时堆栈、页属性变化或 API 调用。
